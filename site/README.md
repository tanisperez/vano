# Vano website

The landing page, install page and user documentation served at <https://vano.tanis.codes>.
Plain HTML, CSS and JavaScript, no dependencies. The only build step generates the documentation
pages. Same structure and stylesheets as Postino's site.

- `index.html`, `install.html`: the pages. The download links point to the latest GitHub release.
- `404.html`: the page GitHub Pages serves for any missing address. Its links are absolute.
- SEO: every page has a description, a canonical URL, Open Graph and Twitter tags with the card
  `img/og.png` (1200x630). The home page has JSON-LD (`WebSite` and `SoftwareApplication`), and
  every docs page a `TechArticle` and its breadcrumb, written by `build.py`. `robots.txt`,
  `site.webmanifest` and `favicon.ico` sit at the root.
- `sitemap.xml` and `llms.txt` (a summary for language models, <https://llmstxt.org>): generated
  at the root by `make docs`, ignored by git. `llms.txt` is `docs-src/llms.txt` with the docs
  pages filled in. Keep its facts in line with the README and the pages.
- `install.sh`: the Linux install script, served at <https://vano.tanis.codes/install.sh> and
  shipped in the release tarball for the in-app updater. `packaging/linux/test-install.sh` tests
  it end to end.
- `docs-src/`: the sources of the user documentation. Not published.
  - `pages/*.html`: one file per page, with only its content: a `title:` and `description:`
    header, a `---` line, then HTML. Code goes in fenced blocks, `` ```lang title="file" ``,
    with `json`, `toml`, `shell` or `text`. Headings without an `id` get one from their text.
  - `template.html`: what every page shares: head, header, sidebar, footer and search dialog.
  - `build.py`: wraps every page in the template and writes `docs/`. The `NAV` list at its top
    sets the sidebar order, the breadcrumb and the Previous/Next links: add new pages there. It
    fails on a page missing from `NAV` or from `pages/`, a broken link or anchor, a missing image
    and an em dash. Python 3 standard library only.
- `docs/`: generated by `make docs` (and by the website workflow), ignored by git. Never edit it.
- `css/docs.css` and `js/docs.js`: the documentation layout, search, the "On this page" list,
  copy buttons and syntax highlighting, copied from Postino's site.
- `css/style.css`: copied from Postino's site. Every color, radius and font comes from the Vano
  design system with the Indigo accent (`docs/design-system.md`,
  `crates/vano-app/src/theme/palette.rs`). Each color token is a `light-dark()` pair, picked by
  `color-scheme`. Every screenshot is in the page twice, `.light` and `.dark`, and CSS shows the
  one for the active theme.
- `js/theme.js`: follows the system theme until the visitor picks one with the header button,
  keeps that choice in `localStorage` and sets `data-theme` on `<html>`. Without JavaScript the
  page still follows the system and the button is hidden.
- `fonts/`: Geist and Geist Mono (SIL OFL 1.1, `fonts/OFL.txt`), subset to Latin, copied from
  Postino's site.
- `img/`: the logo (`packaging/icons/vano.svg`), the 512 px icon and the app screenshots, WebP
  only.
- `video/`: the demo video of the home page, as AV1 WebM, H.264 MP4 and a WebP poster. It plays
  muted and in a loop; `js/demo.js` stops it and shows the controls with reduced motion.
- `screenshots/`: the tooling that regenerates `img/*-light.webp` and `img/*-dark.webp`
  (`make screenshots`), the video (`make video`) and the Open Graph card (`og-image.sh`). It is
  not published.

The numbers of the "Fast and light" section were measured by hand on Linux (a home folder of
782,747 files and 208 GB, warm cache, release build): the scan time from the app's log, the
memory as the PSS of `/proc/<pid>/smaps_rollup`. Measure again before changing them.

Preview locally with `make site`, which builds the docs and serves the site on
<http://localhost:8000>.

Deployed by `.github/workflows/website.yml` on every push to `main` that touches `site/`.
